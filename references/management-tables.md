# 管理层报告中的表格表达

根据用户已给的数据和展示目标选择表格结构；一张表只承担一个主要比较任务。
沿用主技能的设计沟通流程：表数、用途、配色、交付形式与计算口径已确定时直接执行，不重复询问；未确定的处理规则先说明影响。
本技能只制作图片与表格，保留已给的数据范围、类别和说明；不开展原声分析、主题归类、真实性验证、复盘写作，也不自动调用 VOC 技能。

## 1. 先选表的任务与结构

| 表型 | 适合回答 | 推荐行列 | 展示重点 |
|---|---|---|---|
| 管理层重点表 | 同一指标的阶段对比 | 行为核心指标；列为前期、第1周、第2周、关键变化 | 规模、比率、结构分块，突出指定比较列 |
| 策略组与城市表 | 组间与组内的数值差异 | 先组汇总，其下缩进城市；列为基期、后期、变化、轨迹 | 已提供的组别、城市数、基数与变化 |
| 阶段表现表 | 不同时间窗口的表现 | 行为当日、前3日、第1周、第2周；列为日均、CPO、占比 | 各阶段天数和包含关系，避免把重叠窗口相加 |
| 话题/类别矩阵 | 已有类别在各期的分布 | 行为给定类别，列为时期/节日/策略组；附样本量 | 提供好的命中数、分母及互斥标识，映射为数值和色阶 |

合成字段设计示例：`对象｜前7日日均｜第1周日均｜第2周日均｜第2周较第1周｜后14天较前7天｜趋势`。
若还需展示 CPO，使用第二张同结构表或上下分块；不要把日均、总量、CPO、占比和各自增幅全部横向铺开。
总量可在表注或样本量行交代。不同窗口长度按已确认口径以日均比较，不能将14天总量与7天总量画成等长阶段。

## 2. 口径进入表头，而不是藏在脚注

- 日均工单 = 窗口内工单数 ÷ 实际覆盖天数；不足完整窗口时同时列覆盖天数，不把缺失日补成零。
- CPO = 同范围工单总量 ÷ 完单总量；展示为“单/万单”时再乘10,000。组汇总重新合计分子、分母，不平均城市 CPO。
- 关键词占比 = 已提供的去重命中工单 ÷ 对应计价规则工单；多个关键词可以重叠，使用提供好的并集总计，不从明细重跑关键词分析。
- 类别占比按提供的命中数与分母计算并标明口径。词频、工单命中频率、话题占比不互换，不从原始话术重新生成分类。
- 变化列写明基期：“第1周较前7天”“第2周 WoW”“后14天日均较前7天”；不要统一缩写成“变化”。
- WoW 只用于相邻完整周；跨节日或不同长度窗口写“较前期”。占比差用百分点 `pp`，相对增长用 `%`。
- 基期为零时写“0→n”或“新增n”，增幅写“—”；数据缺失写“缺数据”，不可计算写“不可比”，真实零写“0”。
- 输入标明订单覆盖不足时，完整窗口 CPO 留空并在表注说明；不自行缩小日期范围或推算订单补齐。
- 小样本保留基数。不得以大增幅自动排名或用颜色掩盖“基数仅1单”等解释性条件。

## 3. 用层级、排序与列筛选降低负担

1. 表头最多两层：上层区分“规模 / 进线率 / 变化”，下层写时间与单位；避免三层合并导致读者来回找口径。
2. 全部城市总计置顶；策略组行用浅底与加粗，下方城市缩进。不得把组行与其下城市再次加总。
3. 数字右对齐，文字左对齐；小数位、千分位与正负号统一。单位放表头，不在每格重复。
4. 优先保留指定的1–2列变化；其余精确指标放补充表。表过宽时拆成同顺序的两块，不缩到难读。
5. 按已确认的展示目标排序，如变化量、最新值或对象名称；明示依据，不在不同表间无故更换顺序。
6. 保留提供的完整对象列表；需要精简时按已确认规则展示重点对象与“其他”合计，完整数据另表保留。
7. 用户已给的状态或简短说明可单列展示；不自行增加业务判断或复盘结论。
8. 使用细分隔线和留白，少用满格重边框。重点由行层级、变化列与少量色彩形成，不靠每格加粗。

## 4. 条件格式与数据条

- 先定义颜色语义：重点、对照、上升/下降或业务好坏，只选一套稳定关系。同一颜色不能在不同表中含义相反。
- 条件格式优先放在变化列与关键状态列，通常1–2列；数值与正负号始终可见，不能只靠色块传达结论。
- 连续量用顺序色阶；相对基期的正负差可用以零为中心的发散色阶。阈值来自业务规则或明确说明的统计规则。
- 不把“下降”自动染成好消息：工单减少、收入减少、信息不足减少的业务意义不同。没有判断依据就用中性颜色。
- 数据条适合比较同单位、同分母口径的非负规模；条长从零开始。带正负差的数据条必须画零轴。
- 同一列默认共享最小值与最大值；跨表需要比较时固定尺度。不能每格独立缩放后让最大值看起来一样长。
- 数据条在数值后方用浅色，避免遮住文字；仅一列用条长比较，其他列保留纯数字，以防表格变成图形拼贴。
- 缺失不着色，不画零长度条；用中性符号和说明。极值截断必须注明，不能为了色阶好看静默缩尾。

### 条形、状态与构成如何放进同一张表

- 数据条＋色阶＋图标集分别表达“规模 / 偏离 / 状态”，只在三者提供互补信息时组合；不能让同一数字同时染色、画条、加图标而形成三重强调。
- 实际与计划蝴蝶表：两侧从中心向外画等尺度数据条，保留左右身份；差额列给正负数，完成度列给比率。镜像条只是布局，不代表一侧数值为负。
- 实际/计划比通常可超过100%，用进度条或数字并明确超额；不硬压成100%，也不画成“完成＋剩余”的饼图掩盖超额。
- REPT 字符条适合轻量表内比较，但条长依赖字体和字符宽度。不能宣称其精度等同原生数据条；精确数值必须保留。
- 气泡只在需要表达第二个非负规模时使用，面积而非半径与数值成比例，并给参照。负数、缺失、增幅不直接转换成气泡大小。
- 批量迷你饼只适合有真实分母的0–100%构成，每行注明同类占比。增长率、实际/计划超额率与相互重叠话题不能画成饼；精确比较优先用数据条。
- Harvey 球表达预先定义的定性等级，不是实际百分比。`3/4`圆形评分不能写成“完成75%”，除非底层指标确为该比例且另有明确定义。
- 差值柱/差额条以零轴区分正负；跨行采用共同尺度，与绝对规模分开一列。下降是否有利由指标语义决定，不照搬参考截图的红绿配色。
- 上述组合优先选择一个主编码、一个辅助编码。需要同时看量、率、完成度和趋势时，分成两个同顺序的表块，避免整表每格都画图。

## 5. 迷你图：用于看轨迹，不代替数据

- 优先画“前7天→第1周→第2周”或真实逐日轨迹，并在表头给出共同时间顺序；不能将后14天汇总当第4个连续时间点。
- 关键读数与迷你图并存，例如基期值、最新值和 WoW；小图只帮助识别抬升、回落、持续或波动。
- 跨行比较绝对量级时共享纵轴范围；只比较形状可逐行独立缩放，但显著注明“各行独立尺度，仅看方向”。
- 最新点或生效点可加一个重点色，基准线用细灰虚线。避免对每个点加标签，造成比主表还复杂的微型折线图。
- 缺失留断点，不能直接连线暗示完整数据；没有足够的真实观测点时改成文字状态，不造平滑曲线。
- 前后日均与阶段 CPO 可作三点趋势，但需标明是阶段汇总；不要伪装成逐日明细。
- 只有一个点不画趋势；常数序列显示水平线并保留数值。稀疏小基数用数值为主，不靠尖峰制造冲击感。

## 6. 话题/类别热力表的展示规则

- 输入为已经提供的类别、命中数、对应分母、时间窗口和互斥/重叠标识；不读取原声重新分词、归类或验证主题真实性。
- 行名直接使用给定类别，保持原分组；若可多选，注明“可重叠，合计可超过100%”。缺少标识时不推定互斥。
- 格内显示占比，行或列旁保留分母/样本量；低频类别可补数量或日均，避免只见占比变化。
- 比较类别大小时统一色阶；突出同一类别跨期变化时可采用逐行色阶，必须注明“仅行内比较”。
- 逐行色阶不能用于比较两行绝对量级；需要同时展示两种比较时，加统一尺度的总览条形列，而不是混用色义。
- 按提供的缺失标记和窗口信息留白或注释；比例色阶与数量色阶分开标明，不以颜色加深替代数值读数。
- 互斥且合计完整的类别才可用100%构成表/堆叠；多标签主题使用独立比例列，不补一个虚假的“其余=100%−合计”。

## 7. 现有引擎能力与实现路径

以下是当前 CLI 的真实能力，不把表格设计建议写成新增 JSON 字段。字段以 [图表目录](../docs/CATALOG.md) 和脚本为准。

| 现有能力 | 能直接完成 | 不能据此承诺 |
|---|---|---|
| `table_harvey` | 行名、列名、文本、`harvey` 0–4、`check` 布尔及图例的定性比较表 | 任意条件格式、数据条、分组表头、表格内迷你折线或 Excel 联动 |
| `kpi_cards` 的 `spark` | 卡片中的数字序列迷你线；当前实现逐卡用该序列最小/最大值缩放 | 通用表格迷你图列、共享纵轴设置、缺失断点自动处理 |
| `heatmap` | 数值矩阵、统一 `min/max` 与 `low_color/high_color` 色阶 | 自动逐行色阶、缺失值显示、混合文字状态或多层表头 |

`kpi_cards.spark` 至少提供两个有效数值；缺失序列不直接传入。需要共享尺度或断点时使用适合的其他实现。
`heatmap` 不接收空值；不得为了渲染把缺失改成零。逐行色阶且保留原始读数的表，另用 HTML、原生文档或电子表格工具实现。
丰富管理表选普通 HTML/CSS（可内嵌 SVG 迷你图）、Word 原生表格或 XLSX 条件格式/迷你图；保持同一份核实数据。
不复制整套图表引擎，也不创造 `table_sparkline`、`conditional_format` 等并不存在的 CLI 配置。使用新库功能前核实支持情况。

## 8. 按阅读场景交付并检查

- 格式由已确认需求决定，不默认同时交付全部格式；图表技能的16:9画布不意味着 Word 报告也要横版。
- Word 默认正常竖版，表格为可编辑原生表格；宽表拆块、表头跨页重复，不用整页截图冒充可编辑表。
- HTML 使用语义化表格及自包含样式，宽表可横向滚动并固定关键列；打印版另设合理分页，不只检查大屏。
- PPT 表格可以是原生表或形状，明确编辑边界；当前 CLI 输出为形状，不能声称可在 PPT 中“编辑数据”自动重算。
- XLSX 用真实数值、公式、原生条件格式；工具支持时加入原生迷你图。插入 SVG/PNG 的迷你图不称为数据联动图。
- 重新计算并核对总分、比率、覆盖天数、舍入和变化；生成 Word/PPT/XLSX 时按相应工具流程验证实际打开结果。
- 在最终阅读尺寸检查楷体、列宽、重复表头、截断、留白、正负号与颜色语义；正文、图、表必须使用同一版本数据。
- 保存表格的源数据、排序规则、分母、色阶范围、迷你图尺度与来源版本，以便下一次按同口径更新。
