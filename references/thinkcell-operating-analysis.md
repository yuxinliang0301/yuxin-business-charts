## 将教程映射到现有实现

| 教程中的方法 | 何时采用 | 本 skill 的做法与限制 |
|---|---|---|
| Excel 底稿驱动图表（§三.2） | 数据经常更新，需要可复现 | 保留原始数据、计算口径和 JSON spec，数字改变时从源数据重新计算并渲染全部交付物。当前没有 Excel 自动链接；HTML 改字也不更新几何。不要直接改 PNG 或 HTML 数字来伪装数据刷新。 |
| 类别与系列方向（图 018、040–041） | 导入交叉表、堆叠图 | 明确 `categories` 是每根柱/每个时间点，`series[].values` 与其逐项对应。核对首尾类别与总计，排除把合计行再次作为系列。不要把教程 Excel 的行列位置规则机械套到所有 JSON 类型。 |
| 层级差异、总计差异、复合增速（§三.3） | 比较分项、总量或跨期增长 | 先明确比较对象、起止期和分母。现有 `diff` / `total_diff` 默认比较柱总量；不支持自动定位堆叠内某一段。分项差异用独立图或经计算的 callout，不能用总量箭头冒充。复合增速见下文校正。 |
| 值线、均值、中位数（图 031–034） | 判断相对基准的位置 | 用 `value_line.value` 或 `line_target`，先从所选可比样本计算基准，标签写明目标/均值/中位数。引擎不会替 Agent 选择基准；汇总费率、毛利率等由总分子/总分母计算，不能无权重平均分组率。 |
| 折线标签做减法（§四.2–3） | 多时点、多系列 | 标当期、重点极值或有解释意义的拐点，其他点保留必要刻度。`line` 默认只标末点；`combo` 当前会标全部点，稀疏标签需要改用面板、定制或减少显示期数，不要编造选择性标签字段。 |
| 柱表示规模、线表示效率（图 064） | 例如余额与周转天数 | `combo` 可做双轴，两侧单位必须清楚；多个量纲优先共时间轴的独立面板。柱仍从零开始，不能为让线在上方而人为移动尺度。当前 combo 自动定轴，不提供教程的拖轴交互。 |
| 缩减与累计瀑布（图 069–072） | 收入到利润、期初到期末 | `waterfall` / `waterfall_subtotal`：真实起点用 `kind: start`，有符号增减用 delta，小计/期末用 `kind: subtotal/total`，省略小计或期末 value 可自动累计。教程的 `e` 不可直接写入数值字段。若存在独立期末余额，要与累计结果对账，不能只因自动算平就认定业务正确。 |
| 面积表达构成或差额（图 076–079） | 可加总分项随时间变化 | `area` 是堆叠面积。构成项必须互斥可加；表达收入与成本之间的毛利时用成本+毛利，或用收入/成本两条线。不能把收入与成本直接堆叠，详见下文。 |
| 气泡与分区（图 081、088） | 两个指标定位，第三个指标表规模 | `scatter` / `bubble` 支持 `partition: {x, y}`，阈值来自业务定义。教程例子是余额×坏账的一般经营矩阵，不因标题写 BCG 就称为标准 BCG。若大小只是重复 x 值、并无额外信息，可优先普通散点。当前 bubble 半径含最小显示偏移，不是严格面积比例，精确规模比较应保留数值或改用条形。 |
| 蝴蝶图（图 094） | 两组对象沿相同类别比较 | `butterfly`；左右同单位、同尺度、同排序，左右方向只表示分组，不代表负数。重点是变化幅度时优先 `dumbbell` 或 `bar_yoy`。 |
| Mekko 同时看规模和结构（图 096–097） | 市场/客户群大小不同 | `mekko_percent`：宽度=组规模，高度=组内占比；当宽度来自该组总量时，面积才对应该分项绝对量。`mekko_unit`：高度=绝对量，勿解释为占比；若宽高同时使用同一总量，面积会重复放大规模，优先百分比 Mekko 或普通堆叠。 |
| 轴中断（图 098–102） | 极值让其余对象不可读 | 先考虑排序条形、分面或主图加局部图。使用断轴时显式标出断口、区间和原值；断轴后柱长不能用于直接比较倍数，移动断口也无法恢复原始比例。 |

## 阅读教程时必须校正的三类数值问题

以下是对所提供图文的核算，不是用户业务结论。

### 1. 期间增长、平均每期增长和年化增长分开

图 025 的应收余额从 4 月末 72,700 到 9 月末 73,978：

- 期间增长 = `73,978 / 72,700 − 1` ≈ **1.76%**。
- 首末时点之间有 **5 个月间隔**，按月间隔折算的年化增长 = `(73,978 / 72,700)^(12/5) − 1` ≈ **4.27% p.a.**。按实际天数折算时应明确天数约定。
- 图中约 4% 的 `p.a.` 不能描述成“9 月底比 4 月底上升 4%”。

现有 `cagr` 装饰按类别下标间隔 `to−from` 计算复合每期增长，不解析日期：相邻类别是年才默认是年复合；月度类别需明确标为月复合。年化或不等距时间先计算实际期间，再写明确 `label`（仍需满足该装饰要求的正起止值和递增索引），或用普通注释。零基期、负值跨零不能套常规 CAGR，改绝对差值并说明。不要通过省略中间月份来改变自动计算的期间数。

### 2. 箭头连接的时点决定同比/环比名称

图 023/025 的坏账末值为 10,855；相对 4 月的 9,915 增长约 **9.48%**，相对 8 月的 10,575 则增长约 **2.65%**。因此图中 +9% 不能写成“9 月环比 +9%”。每条差异注释都应核对起止标签，不能按箭头摆放在最右边就推断它是环比。

### 3. 堆叠面积顶部是求和，不是两条曲线之间的差

图 078 中 1 月收入 39、成本 15；图 076 顶部约为 54，符合两者堆叠之和。上层色带厚度是收入 39，**不是毛利 24**。

若要保留面积表达：计算 `毛利=收入−成本`，传入毛利和成本两项，让顶部等于收入，底部带为成本、上层带为毛利。本引擎 `area` 反向遍历 series，故上层毛利写在前、下层成本写在后。出现负毛利时不直接使用当前非负堆叠面积，改用收入/成本折线并单列毛利差额。series 标签必须写真实分项，不用“收入”冒充“毛利”。

## 把底稿变成可重复更新的图表

普通单图保留源 spec 即可；周期性经营汇报额外记录原始文件/表页/范围、指标单位、时间范围、筛选条件和计算公式。底稿更新后按同一口径重新计算，核对总计与首末值，再生成用户需要的格式。布局尽量复用，但不能通过修改显示标签跳过重算。

目标类图优先与同截止日的分期计划比较。有季节性时，日历时间进度只能作为辅助基准；没有分期计划就明确这一限制，不能仅凭落后线性时间进度判定经营不达标。

配色继续沿用 `restrained_navy`：对照灰、当前深蓝、负差/缺口酒红。颜色表达数值方向和业务好坏要分开；例如回款是应收余额的负项，不能因此叫“坏影响”。字体与交付载体统一；只有真实重点才用强调色。

本次新增的可运行示意 spec（均为重新构造的数据）：

- `examples/restrained/receivables-bridge.json`：起初余额+新增−回款−核销=期末，期末自动累计并与独立余额核对。
- `examples/restrained/cost-profit-area.json`：成本+毛利=收入，避免收入和成本重复堆叠。

这些是对原有类型的正确应用，未增加图表类型数量，也未实现插件数据联动。
