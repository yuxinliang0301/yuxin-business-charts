# Bainflix 案例中的图表论证与版式

## 来源和适用范围

用户提供《【初赛案例】Bainflix+香港大学+赵安琪.pdf》，28 页，封面为 2022 Bain Cup Case Competition。SHA-256：`df90a13be7f69f4739a69d14a41905719ec6124085563ee08ef8972cbc32da2c`。已提取全部文字、通览 28 页渲染图，并放大核对 p4、p6、p11、p18、p19；页码为 PDF 物理页码。

借鉴的是图表的论证关系，不把参赛案例当成官方设计标准或今天的商业事实。2022E–2026E 是案例当时的预测；不能因为年份已到就改写为实际。下列是本地适配规则，后续不依赖源 PDF。

用户已指定全楷体、PNG + 可编辑 PPTX，优先于原稿英文字体。原稿大面积鲜红、粉红、密集虚框和小字号不作为本地默认；仍用白底、蓝灰、少量语义强调。

## 一页如何建立论证

1. 先确定本页要回答的问题，再选互补证据。标题写数据能支持的判断；方法说明页可用明确的主题标题，不硬造结论。
2. 用两块有分工的证据回答判断的不同部分。例如规模增长与结构迁移、渠道覆盖与单店产出；不要用柱图和折线重复同一组数据凑版面。
3. 每块证据下留一两行解释，讲该读数意味着什么、有什么限制；不要把全部标签又抄一遍。图与解释上下对齐，属于同一阅读单元。
4. 证据能支持行动才写行动；机制假设和已观察事实分开。渠道覆盖低不自动证明扩点能盈利，相关变化不自动证明策略有效。
5. 用统一边距、结论标题、细分隔线和同尺度形成秩序；不要用许多彩框或装饰图标替代逻辑。单张图不需要整套报告导航。

## 可迁移的证据结构

| 案例页 | 表达结构 | 本 skill 采用方式 |
|---|---|---|
| p2 | 市场/竞争/消费者发现 → 分组策略 → 目标 | 用于检查图表之间的关系，不自动扩大成整本报告。目标写成目标，不能与已验证结果混淆。 |
| p4 | 总市场规模 + 细分占比 + 驱动解释 | 规模用堆叠柱，结构用 100% 柱；同实体同色。历史/预测类别带 A/E，数据不等距时不把柱间距当连续时间。CAGR 写清起止年；驱动解释须有独立证据。 |
| p5–6 | 竞争定位/进入者变化 + 多指标对照 | 可用散点/排序条形与对照表；规模、占比、等级各自保留单位。表内微条只在同一行同尺度。不能把同页“网点总数”与“线下网点数”混成同一指标。 |
| p7 | 样本特征 → 人群画像 → 购买标准 | 先标样本量、筛选条件和调查时间，不能把样本当总体。访谈原话必须有来源；构造画像要标示意。精确比较重要性与表现时，成对条形通常比雷达更易读。 |
| p9、23–24 | 指标体系 → 评分 → 分层 → 地图 | 评分过程与结果分开，披露标准化、权重和阈值；不沿用案例 80/20 权重。地图和复杂指标树需定制；无地理问题时用排序条形。 |
| p10、12–14 | 分组特征 → 对应措施 → 预期效果 | 同组内的依据和动作对齐，跨组用相同比较维度；效果标预期。文字策略矩阵不是现有 dashboard 的任意子图类型，需原生表格/形状定制。 |
| p11 | 渠道 × 评价维度 → 优先机会 | 定性等级先定义评分依据；未评估留缺失而非零分，不能仅凭填色制造精确度。量化数据可用 heatmap，解释文字多时用可编辑表格。 |
| p16 | 现状问题 → 机制调整 + 业务流/数据流 | 明确区分现状与方案、商品流与反馈流；连接线表示有定义的关系。流程图需定制原生形状，不冒充已支持图型。 |
| p18、26–28 | 情景预测 + 利润趋势 + 增量来源 + 底稿 | 同一基准预测应在曲线、瀑布与底稿对上；情景不是置信区间，也不是承诺。渠道增量=期末−期初，不能拿期末绝对量做桥。现有 dashboard 不含 waterfall 子图，可拆成两页或定制组合。 |
| p19 | 时间路线图 + 优先级 + 风险对策 | 甘特只表示时间，优先级另列；每条主要风险对应可执行应对。只有“短/中/长期”时不虚构具体日期，用阶段表，或待排期明确后再用 gantt。 |

## 本地版式与字体

- 主标题通常 24pt 楷体加粗，面板标题 14–16pt，图内读数 12–14pt，解释 12–14pt，来源至少能在最终交付尺寸读清。不能为了复制原稿密度一直缩小楷体。
- 默认两块互补证据；宽度服从信息量，不强制等宽。三块证据仅在都能读清时使用。正文采用原生文本，条线和数字也保持可编辑。
- 编号用于阅读顺序，不要求每页都有编号；导航只在确有跨页结构时出现。来源、单位、A/E、样本量与口径是必要信息，优先于装饰。
- 基准/对照灰、当前/重点深蓝；预测用明确 E 标签及说明，必要时再用线型区分。酒红仅在定义清楚的缺口/负差出现。不同证据面板中的同一实体维持同色。

## 已实现的可复用接口

这些是 dashboard 的布局选项，未增加单图类型数量：

```json
{
  "type": "dashboard",
  "exhibit": true,
  "font_family": "Kaiti SC",
  "theme": "restrained_navy",
  "panels": [{
    "title": "01 / 规模变化（万元）",
    "title_size": 15,
    "insight": "该读数的业务含义；必要时说明局限。",
    "insight_size": 13,
    "insight_height": 0.8,
    "chart": {"kind": "column_stack", "data": {"categories": [], "series": []}}
  }]
}
```

此片段只示意字段，需填真实数据、来源与完整标题后校验。`exhibit: true` 在标题下加细线；每个 panel 的 `insight` 在其图下预留独立解释区，不覆盖图形。`insight_height` 单位为英寸，默认 0.75；适合 1–2 行，超长解释需缩写或拆页。剩余图高不足时渲染会报错，不自动挤压。`facet` 不提供逐格 insight，需此结构时用 dashboard。

可运行示例均使用重新构造的数据：

- `examples/restrained/market-opportunity.json`：总量增长与结构变化互相印证，区分历史和预测。
- `examples/restrained/coverage-productivity.json`：覆盖与单店产出呈现经营矛盾，行动建议保留试点条件。

输出前核对标题与数据、两图的实体/时期/口径一致性、预测标识、楷体是否实际生效、解释区是否溢出，以及 PPT 中没有把整页截图当成可编辑图表。
